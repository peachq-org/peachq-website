lint.q

A linter for q source. It reads the text with .pq.syntax and runs none of it but the literal-only parts of built-in operators that LITERAL_ERROR evaluates, and type checks on literals, under reval. Rules carry KX QLint's IDs, but PARAM_TYPE_MISMATCH, qStudio's, and the hazard rules (valid q you probably did not mean), SYNTAX, LITERAL_ERROR and TYPED_PARAM_ERROR, which are peachq's. A comment "@qlintsuppress RULE(n)" silences RULE on its own line and the n below it, a bare RULE silences it in the whole file and the rule all matches every rule. A statement that does not parse reports only that: SYNTAX, or ASSIGN_RESERVED_WORD for an assignment to a reserved word. A string is always source and a symbol always a path: lint never guesses which.

Examples

.lint.text "f:{[a;b] a+1}\ng:$[1b;2;0b;3]"

Entity Details

.lint.explain[rule]

What one rule finds and why it matters. A rule .lint.rules[] does not list signals, saying whether it is a KX QLint rule peachq lacks.

Parameters:
  • rule - (symbol) a rule ID

Examples

.lint.explain `UNUSED_PARAM

.lint.main[args]

The q -lint command line, answering its exit code: args are the words after q, paths and -format text|json|sarif, or -help (--help, -h) for the usage. Findings and the asked-for usage print to stdout; a notice, or a usage error naming what was wrong, to stderr. The code is 0 for -help; 2 for a usage error or an input that is missing or cannot be read, whatever else was found; else 1 for a finding of severity error; else 0.

Return: (long) the exit code
Parameters:
  • args - (list) the words, each a string

Examples

.lint.main ("src";"-format";"json")

.lint.path[p]

The findings for files, and for every .q file under directories, with a leading file column. Each file takes the settings of the lint.config files above it, as q -lint does. A path that does not exist signals, naming it.

Parameters:
  • p - (symbol) a file or directory handle, `:path, or a symbol list of them

Examples

.lint.path `:src

.lint.rules[]

Every rule: its severity, whether it runs unless opts says otherwise, and what it finds.

Examples

.lint.rules[]

.lint.run[target;opts]

The findings for source text or paths, with settings: opts maps a rule to 1b (run it), 0b (do not) or a severity, `error, `warning or `info (run it at that severity), over the on and severity columns of .lint.rules[]; any other value is 'domain. An ID that is no rule this build has is ignored, with a notice on stderr, so stored settings outlive a rule. Two more keys are options: positions, `utf8 (the default, col and endcol count bytes) or `utf16 (UTF-16 code units, as Java, JavaScript and LSP count, a character past U+FFFF two); and globals, a symbol list of names defined elsewhere, which every rule takes as defined. Every file one call lints is one project: a name any of them defines is defined for all. For a path, a file's lint.config settings apply first and opts over them. A string is source and a symbol a path, always: .lint.run["src/a.q";::] lints the text src/a.q.

Parameters:
  • opts - (dict) rule!boolean or rule!severity, and the options positions and globals
  • target - (any) source text (string), or paths (symbol), as for .lint.text and .lint.path

Examples

.lint.run["f:{[a;b] a}";(enlist `UNUSED_PARAM)!enlist 1b]
.lint.run["a:$[1b;2;0b;3]";(enlist `COND_EVENARGS)!enlist `warning]
.lint.run["f:{g x}";`UNDECLARED_VAR`globals`positions!(1b;enlist `g;`utf16)]

.lint.text[src]

The findings for q source text, one row each, by position, judged by kdb's grammar whatever the session's \classic (a trailing qSQL comma is SYNTAX). line and col are 1-based, col counts bytes, and endline/endcol name the last byte a finding covers. src is always source, even text that names a file: a path is a symbol, for .lint.path.

Return: (table) ([] line; col; endline; endcol; rule; severity; msg)
Parameters:
  • src - (string) the text of a q file, or a char atom

Examples

.lint.text "f:{x+1\ng:$[1b;2;0b;3]"
