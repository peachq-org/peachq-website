hash.q

Non-cryptographic hashes - xxHash (xxh32, xxh64, xxh3_64, xxh3_128), rapidhash and MurmurHash3 - for bucketing, keying, sampling and fingerprinting (md5 and .Q.sha1 are the digests). Every function hashes the bytes of a string, a byte vector or a symbol (its text); a char atom is one byte. A symbol vector, or a list of those subjects, answers one hash per element in a single call (a list of one-char strings is spelt (enlist "a";enlist "b") - ("a";"b") is the string "ab"); anything else is 'type. A 32-bit hash rides a long; a 64-bit hash is the long with the same bit pattern (negative when the top bit is set); a 128-bit hash is 16 bytes, a list of them over a collection. The plain forms use seed 0; .hash.seeded takes the seed explicitly. The values are those of DuckDB's hashfuncs extension for the same bytes and seed, so a key bucketed in q matches one bucketed in SQL.

Examples

.hash.xxh64 "hello world"
.hash.xxh64 `AAPL`MSFT`IBM
.hash.seeded[`murmur3_32;42;"hello world"]

.hash.seeded[algo;seed;data]

Any of the eight hashes with an explicit seed; seed 0 is the plain form.

Return: as the algorithm's plain form; a vector (or list of 16-byte vectors) over a collection
Parameters:
  • seed - (long) any integer atom: xxh32 and the murmur3 hashes take 0 to 4294967295, the others any 64-bit pattern (-1 is the seed 18446744073709551615)
  • data - (any) the string, byte vector, symbol or char to hash, or a symbol vector / list of those for one hash each
  • algo - (symbol) one of `xxh32`xxh64`xxh3_64`xxh3_128`rapidhash`murmur3_32`murmur3_128`murmur3_x64_128; the same name as a string also reads
throws:
  • domain - an unknown algorithm, or a 32-bit seed out of range
  • type - data (or an element of it) is not text, bytes or a symbol, or seed is not an integer

Examples

.hash.seeded[`xxh64;42;"abc"]
.hash.seeded[`murmur3_32;42;("abc";`abc;0x616263)]
